# 单仓 Native 状态查询回归迁移

依据为 `report:2026-11-10-agent-platform-execution` 及 [上游 PR #554](https://github.com/rpamis/comet/pull/554)。上游将只读状态查询从工作区产物路径和便携检查点对账中移出。fork 的原报告 `report:2026-11-10-native-multi-repo-ci`、案号 `native-group-single-repository-status-observation` 和断言正文按 `31c780e7` 原样归档。

- **普通状态查询**。旧测试要求无清理收据时恰好解析一次产物路径。当前查询直接读取 SDK Run，检查零次完整产物路径解析。重复查询仍读取权威状态，且不更新 Run revision，不用与 Run 不一致的便携检查点覆盖结果。
- **产物链接**。旧状态查询因解析 `docs/comet` 而拒绝其被换成链接。当前查询不使用该目录，链接存在时仍返回原状态。实际访问产物时继续拒绝同一链接。旧测试通过修改内存中的阶段来触发产物路径解析，当前测试直接调用真实路径访问边界。
- **清理收据**。清理历史仍位于独立 Runtime。测试在正常查询之后将收据路径的上级目录创建为链接，验证下一次状态查询拒绝该路径，未改写链接目标或 Run revision。

迁移保留“不重复解析、只读观察不复用便携投影、实际受保护读取拒绝链接”三项保证。仅依赖普通 `status` 发现产物目录链接的行为随上游调整；此处没有改变 Runtime 实现。
